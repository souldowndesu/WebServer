# 认证管理平台架构决策

## 目标与非目标

目标是用一个后端替换临时的时钟与匿名聊天试验：账号登录、管理员账号池、用户隔离、全员可见目录、申请式连接、受限通讯、代理入口、只读日历同步、个人博客和远程推理任务下达。

本阶段不提供正式前端美术、不实现推理算法、不在明文公网部署登录、不允许聊天附件，也不允许自定义博客执行 JavaScript。

## 权限模型

- 未登录：只有健康检查和 API 元数据。
- 普通账号：维护自己的资料、头像、设置、备注、设备、日历、连接、消息、博客和推理任务。
- 管理员：普通账号权限，加账号创建/停用/角色/密码重置、博客审核、Worker token 创建和服务器全局代理修改。
- 管理员不能读取任意私人会话，也不能读取密码或令牌原文。
- Device token 只有 `planner_sync` 权限；Worker token 只有领取和回报任务权限。

浏览器会话使用 HttpOnly SameSite=Strict cookie；公网 HTTPS 模式另加 Secure 和 HSTS。cookie 修改请求另需 CSRF token。API 测试或受控客户端可使用 Bearer session。所有带 Origin 的修改请求必须与 Host 同源。登录失败按账号名与来源地址做滑动窗口限速；只有连接本身来自 loopback 时，后端才可信任由本机反向代理覆盖写入的 `X-Real-IP`。

## 一致性与隔离

账号私有文件在各自随机 id 目录内原子替换。跨账号关系、消息、审核和任务必须使用共享 SQLite 事务。这样既能直观看到同级账号结构，又避免把同一条双方消息复制两份造成分叉。

当前服务假定一个正式应用进程；文件层使用进程内可重入锁，SQLite 负责跨线程事务。如果未来需要多进程或多机水平扩展，账号 JSON 要迁移到事务数据库或增加操作系统级锁，不能直接启动第二个写进程。

## 旧数据迁移

旧聊天室只保留最多 200 条进程内消息，没有持久磁盘数据可迁移。移除源模块后，旧服务重启或停止即清空内存。新系统不导入匿名作者，因为无法可靠映射到账号。

旧代理页面的安全白名单逻辑被移动到 `control_plane/proxy.py`；原独立静态页面和端点不保留兼容入口。代理是服务器全局资源，状态读取和修改都只允许管理员。账号设置不再保存无实际作用的“偏好模式/节点”；管理员开启后，明确配置到 `127.0.0.1:7890` 的服务器进程共享同一状态。

## IrohaWalendar 映射

网页结构应保留命令栏、视图切换、目标/行动与日常规划侧栏、日/周/月、统计和设置的层级；视觉令牌改为网页管理后台统一体系。网页不创建、拖放、确认或删除日历实体，只显示桌面端上传的最新 v5 快照与“最后同步/设备状态/只读”提示。

完整快照方案优先满足现有桌面应用的原子 `planner-state.json`。如果以后需要离线多设备双向编辑，再引入参考草案中的 operationId、deviceId、baseRevision、cursor、tombstone 和冲突面板；本期不要假装已经实现增量冲突合并。

## 推理任务状态机

```text
queued → running → succeeded
   │        ├────→ failed
   │        └────→ queued（租约过期）
   └─────────────→ cancelled
```

领取按优先级降序、创建时间升序。Worker 获得 5 分钟默认租约，进度上报续租；完成后租约摘要立即清空。结果为不超过 2 MiB 的受限 JSON。大文件结果未来应上传到带配额的对象存储并只回传内容哈希与受控引用。

## 部署闸门

合并产品 PR 不等于正式部署。旧 connectivity-chat、独立 proxy-control、UFW 8765 和内存聊天数据已通过环境 PR #22/#23 退役。新平台部署前仍必须单独记录环境变更，至少包含：建立低权限服务账号与私有数据目录；从审核后的 main commit 安装只读代码；配置公网 IP 证书、TLS 反向代理、自动续期、Secure Cookie 与仅本机代理信任；通过无回显流程初始化唯一管理员；验证备份、恢复、权限、证书续期、端口以及 Mihomo 和 SSH 不受影响。公网只开放 80/443，应用端口保持 loopback。
